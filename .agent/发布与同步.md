# 发布与同步

更新：2026-10-17。源码事实来自工作区（版本 1.3.0）；线上布局仍依据 2026-10-08 核查，之后仅部署过 2026-10-09 的车手补齐与多选上传修复。安装包状态见下方“本地打包”。

## 本地打包

开发需要 Windows、Node/pnpm、Rust stable、MSVC 工具与 WebView2；普通安装用户无需开发环境。SQLite 编入程序，AiM DLL 与 FFmpeg/ffprobe 由安装器释放。WebView2 当前是 embedBootstrapper，不能据此保证无网络电脑也能完成运行时安装。

~~~powershell
pnpm install
pnpm dev
pnpm build:exe   # 仅 EXE
./build.ps1     # NSIS + 更新签名
~~~

同步 package.json、src-tauri/Cargo.toml、tauri.conf.json 三处版本为三段版本号（当前均为 1.3.0）。build.ps1 读取 .secrets/signing/scut-updater.key 与 password.txt，导出 TAURI_SIGNING_PRIVATE_KEY(_PASSWORD) 等变量后运行 `pnpm tauri build`，结束时清理这些环境变量；私钥丢失会影响使用当前公钥的更新链路。

输出：

- `target/release/scut-racing-telemetry.exe`
- `target/release/bundle/nsis/SCUT Racing Telemetry_<版本>_x64-setup.exe` 与相邻 `.exe.sig`

分发用安装器，云端上传安装器与对应签名。只改源码不会更新现有 EXE。

**当前安装包内容**：前端、Rust 后端、5 个 AiM DLL（释放到 `aim/`），以及 `resources/ffmpeg.exe`、`resources/ffprobe.exe`（映射到安装目录 `resources/`）。2026-10-13 已生成 1.3.0 NSIS 包（68,097,904 字节，约 64.9 MB）及签名，安装后可独立完成 Overlay 视频导出。data 不作为打包资源；升级/卸载行为以实际 NSIS 脚本为准，不能沿用旧设计承诺。`resources/` 在 .gitignore 中，换机后需自备 FFmpeg 才能打包。

1.3.0 之前的安装包在 `target/release/bundle/nsis/archive/`（1.0.0 / 1.0.1 / 1.2.0 / 1.2.1 / 1.2.2，含签名），可另行归档。

## 数据同步

localStorage：scut.remote-server-url、scut.remote-token、scut.remote-autosync。自动同步默认开，缺地址/密钥跳过；手动同步显示缺少的记录。

1. 带 Bearer 令牌取索引，与本地完整 file_hash 求差。
2. 顺序下载全部缺少文件到 data/cloud-downloads（文件名沿用索引中的原文件名）。
3. 逐个调用导入管线并等待任务结束，再按 SHA-256 去重、归档源文件、写 raw 与 SQLite。
4. 导入尝试后清理中转副本，恢复 UI，汇总新增/重复/失败；列表刷新时合并日期备注。

Rust 下载参数要求 url、token、fileHash、fileExt、fileName；前端发送 { url: baseUrl, token, fileHash, fileExt, fileName }。旧 EXE 使用 baseUrl 参数导致失败，2026-10-08 本地重打包纳入了修正。

这是完整文件增量拉取，不是 SQL 文件同步或字节断点续传。本地备注/偏好不回传，云端删除不传播。尚未解决：失败明细只显示数量、下载取消、日期备注离线落库、同哈希元信息更新。

## API、身份和文件

| 接口 | 权限与用途 |
| --- | --- |
| GET /health | 公开，检查服务/数据库连通；不验证客户端密钥 |
| GET /api/v1/datasets、/date-notes、/files/:hash | Bearer 客户端读；合法管理员会话也可读 |
| /api/v1/admin/session、/login、/logout | 会话生命周期 |
| /api/v1/admin/accounts、/password、/tokens | 账号/密码与客户端密钥管理 |
| /api/v1/admin/uploads、/datasets、/files/:storage_key | 上传、索引、归档、删除与管理下载 |
| PUT /api/v1/admin/date-notes/:date | 管理员共享日期备注 |
| /api/v1/admin/releases | 发布、安装器与签名管理 |
| GET /api/v1/updates/latest、/updates/files/:hash | 公开软件版本检查和下载 |

管理员密码 scrypt 散列，会话 7 天，Cookie 为 HttpOnly / SameSite=Lax，按 IP 限制失败登录。客户端令牌原文存 PostgreSQL，管理员可查看/吊销。需要 SCUT_ADMIN_PASSWORD 初始化并启用管理员功能；普通队员只读。

上传 XRK/XRZ：解码文件名（先 decodeURIComponent 再清洗）→ SHA-256 保存 → xrk-meta 提取 → SQL 入库。上限 512 MiB，当前采用内存缓冲。DELETE datasets 会删索引并尝试删实体文件；“删除不删文件”是过期交接描述。

车手优先采用文件内 RCR；为空时，上传层从“车手_已知车辆_场地…”格式的原文件名补齐（以车辆名为锚点取前缀，哈希名不参与），无法匹配则留空。2026-10-09 已部署此补齐规则和管理页多选上传，并修复现有四条空车手 XRZ 索引；其余本地服务器改动不因此视为已部署。

PG 表：datasets、date_notes、admin_accounts、admin_sessions、client_tokens、releases。启动幂等执行 schema.sql；uploads 存原文件和安装器，SQL 保存 storage_key / installer_key。

## 软件发布

草稿 → 上传 setup.exe → 上传对应 .sig → 发布。最新版本选取已发布且安装器/签名齐全的记录，按三段数字比较。管理员网页排序修正目前只确认本地，需部署后另查。

Tauri updater 验证安装器签名，公钥来自 tauri.conf.json。静态 endpoints 已清空；`check_for_update(base_url)` 校验地址只含协议/主机/可选端口，再拼 `/api/v1/updates/latest`，超时 15 秒。数据同步与软件更新共用用户填写的 Base URL，安装包不内置服务器地址。配置仍允许非 HTTPS 传输（dangerousInsecureTransportProtocol）。1.3.0 安装包已按此源码构建，但尚未发布到云端。

## 部署

本地入口见 [server README](../server/README.md)。最新 config/start-server 从 .secrets/server.env 或环境变量读取凭据，不再提供默认连接密码；compose 要求 SCUT_DB_PASSWORD。2026-10-08 核查 ECS：

~~~text
/opt/SCUTRacing/
  app/             # server 源码、compose、.env、bin/xrk-meta
  data/postgres/   # PG bind mount
  data/uploads/    # 原始文件与安装器
~~~

宿主机 80/8787 映射到 Node 容器 8787，PG 仅映射宿主机 127.0.0.1:5432。主机改源码后需要 docker compose up -d --build；保留 .env 与 data。SSH 用户 admin 可 sudo，修改 authorized_keys 保留既有密钥。

Dockerfile 依赖预编译 server/bin/xrk-meta，复制后 chmod +x，并非历史计划中的自动 Rust 多阶段编译；部署前准备 x86_64 musl 解析器。服务器代码部署与桌面软件发布是独立操作。

## 已知运维事项

- HTTPS 迁移同时处理 updater 端点、数据地址、代理后的下载 URL origin 和 Secure Cookie；旧客户端仍依赖 8787，保留过渡兼容。
