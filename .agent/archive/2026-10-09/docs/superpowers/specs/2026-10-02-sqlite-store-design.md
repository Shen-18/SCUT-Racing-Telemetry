# SQLite 总索引设计

状态：方案 A 已确认，细化设计待审阅；尚未实施。

## 目标与范围

SQLite 成为记录列表、记录备注、日期备注和分析偏好的唯一正式存储入口。保留现有遥测二进制缓存及 manifest.json，由 cache-core 负责图表读取和缓存校验。整个应用可离线使用，SQLite 随程序编译打包，无需安装数据库服务。

本次设计预留联网扩展的身份和接口边界，不实现账号、服务端、联网同步或冲突合并。实现顺序是总索引迁移、备注功能、通道偏好；每阶段独立验收。

## 数据目录

默认使用安装目录下的 data/telemetry.db，遥测文件仍在 data/datasets/<hash>/。统一使用应用当前解析出的数据根目录；SCUT_CACHE_ROOT 覆盖设置对数据库和缓存同时生效。数据库保存相对缓存路径，移动整个 data 目录后可继续使用。

首次运行创建目录和数据库。安装、升级不得覆盖用户数据。目录不可写时报告实际路径和原因，不静默切换到其他位置。卸载默认保留用户数据，清除数据应是明确的可选操作。

## 模块职责

- telemetry-store：SQLite 连接、结构迁移、事务、记录查询、备注、偏好，以及旧缓存索引接入；对外提供业务方法，调用方不编写 SQL。
- cache-core：原始通道文件、金字塔缓存、manifest 的格式与完整性。
- Tauri：协调导入、删除、启动恢复，将 store 的数据转换为 IPC 返回值。
- 前端：展示数据库结果，通过命令修改备注与偏好。

缓存事实以 cache-core 校验结果为准；数据库保存其索引及状态。备注、偏好以 SQLite 为准，缓存扫描不得覆盖这些用户数据。

## 数据结构

使用版本化结构迁移，启用外键，写入使用事务，配置有限的锁等待时间。SQLite 采用 bundled 编译方式。

| 表 | 主要内容及约束 |
| --- | --- |
| datasets | 稳定 UUID 主键、唯一 file_hash、文件名及类型、会话、车辆、车手、原始日期文本、规范日期、开始时间、时长、通道数、大小、源修改时间、相对缓存目录、缓存状态、创建及更新时间 |
| record_notes | dataset_id 唯一且为外键，每条记录一份可编辑备注、更新时间；删除记录时级联清除 |
| date_notes | 规范日期唯一，每一天一份可编辑备注、更新时间；当天无记录时仍保留备注 |
| dataset_preferences | dataset_id 外键，每条记录的偏好标记及更新时间 |
| dataset_selected_channels | dataset_id 与 channel_key 联合唯一，position 保存通道顺序 |

日期按记录源提供的日期规范为 YYYY-MM-DD，保留原始文本。无法可靠解析时归入“未知日期”，不猜测日期，也不提供该分组的日期备注。

通道按稳定 channel_key 保存，重新打开时过滤已不存在的通道。偏好行存在但无选中通道表示用户明确选择为空；不存在偏好行才使用现有默认选择。

稳定 UUID 用于未来跨设备引用，file_hash 用于内容去重；两者不能使用当前打开会话的临时整数 ID。时间字段统一保存 UTC，记录日期保留原始业务含义。未来通过独立同步模块调用 store，服务端身份映射、删除标记和冲突规则在实现联网时再设计，不把本地 SQLite 文件直接共享为网络数据库。

## 旧数据迁移与一致性

首次接入扫描现有 manifest，校验后按 file_hash 幂等写入索引。每批写入使用事务；中断可重试，不重复创建记录，不改动遥测文件。无效 manifest 报告目录和原因，继续处理有效目录。数据库结构版本与旧目录导入进度分别记录。

正常列表查询直接读 SQLite。导入时先完成缓存写入，再更新数据库索引；数据库写入失败保留缓存并报告，下一次启动对账补录。启动恢复比较目录与索引，必要时读取发生变化的 manifest，不在每次列表查询时全目录扫描。

删除先将目录移至同一数据根下的待删除区，再通过数据库事务移除记录与关联信息，成功后清理目录。失败恢复原目录；启动处理未完成的待删除操作，避免记录被重新扫描“复活”。日期备注独立保留。

数据库损坏时报告错误并保留原文件，不自动覆盖重建。缓存可恢复记录索引，但不能恢复只存于 SQLite 的备注与偏好。结构升级前执行 SQLite 一致性备份；后续备份整个数据目录时需包含数据库和遥测文件，不能在写入过程中仅复制主 db 文件。

## 交互

数据库页面记录操作栏和右键菜单提供“编辑备注”，记录列表展示备注摘要。日期分组右键菜单提供“编辑当天备注”，日期标题旁展示摘要。编辑允许多行文本，保存后立即更新，空文本代表清除备注。

分析页面打开记录时恢复上次通道顺序；通道选择变更通过合并写入保存，离开页面前提交未完成保存。保存错误应展示可理解的反馈，不能假装保存成功。

## 验收

1. 现有记录迁移前后数量和主要元数据一致；重复启动不产生重复行，中断迁移可恢复。
2. 备注、日期备注、通道选择在重启后保留；扫描缓存不覆盖用户编辑。
3. 导入、删除失败及中断后，索引与目录可恢复到一致状态。
4. 移动完整 data 目录后仍能读取图表，原图表缓存格式及性能不受总索引迁移影响。
5. 全新安装无需数据库环境，能创建数据库、导入、分析并保存备注；升级保留已有数据。
6. 包含针对迁移和事务失败恢复的测试，以及 Rust 编译、前端类型检查和安装包实际运行验证。
