# 数据记录同步方案（桌面端 ← 云端）

> 2026-10-07 · 状态：**已实施**（同日完成，决策点按推荐项落地：启动自动下载/删除不回传/云端备注优先/顺序下载/按文件粒度/中转导入后清理/密钥存 localStorage）
> 目标（负责人原话）：管理员在面板上传文件、写备注，客户端每次启动/点按钮拉取最新索引，和本地比对，有新文件就拉下来。"就这么简单"
> 验证：162 前端测试全绿 + tsc 干净 + cargo check 过 + 真实服务器 E2E（令牌鉴权/索引/备注/按哈希下载 sha256 一致）
> 待办：负责人 GUI 实测 → 随下一版本（1.3.0）发布

## 一、现状盘点

### 云端（全部就绪，零改动）
| 接口 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /api/v1/datasets` | Bearer 令牌 | 全量索引（哈希/文件名/日期/车手/车辆/场次/大小等） |
| `GET /api/v1/date-notes` | Bearer 令牌 | 管理员维护的每日备注 |
| `GET /api/v1/files/:hash` | Bearer 令牌 | 按内容哈希下载，512MB 上限 |

### 桌面端（已有积木）
- 设置页「云端服务器」卡：地址输入 + 测试连接（存 localStorage）
- Rust `cloud_download_file(url, token, hash, ext)`：下载到 `<缓存>/cloud-downloads/<hash>.<ext>`，已注册
- `start_import(path)`：完整导入管线——**自带 SHA-256 去重（Duplicate 状态）**、导入时把源文件拷贝进数据目录归档、进度事件齐全

### 缺口
1. 设置页没有「访问密钥」输入框（分发页给队员的就是 地址+密钥 对）
2. 没有"拉索引 → 比对 → 下载 → 导入"的编排
3. 没有同步进度 UI；下载中转文件导入成功后无清理

## 二、方案总览

```
启动（若开启自动同步）/ 手动点「立即同步」
  → GET /api/v1/datasets（带密钥）
  → 与本地 file_hash 集合比对 → 得到新增清单
  → 逐个（顺序）cloud_download_file 下载到中转目录
  → start_import(中转路径) 复用现有管线（去重双保险）
  → 全部完成后：删除中转文件 → 刷新列表 → 拉取日期备注合并
```

任何一步中断都无一致性风险：比对按哈希增量、导入管线再兜底 Duplicate，重跑即续传。

## 三、交互设计

- **设置页**「云端服务器」卡扩充：访问密钥（密码框，存 localStorage）· 「启动时自动同步」开关（默认开）· 立即同步按钮 · 上次同步时间 + 结果（成功 N 条 / 失败 M 条）
- **DATABASE 页**：检测到云端有新记录时显示提示条「云端有 N 条新记录 → 立即同步」；同步进行时复用底部 ImportProgressBar 槽位显示「下载 2/5 xxx.xrz」「导入 3/5」
- **新成员装机即用**：装好软件 → 设置页填地址+密钥 → 自动全量拉库。这是本功能的最大收益（新队员零教学上手）

## 四、细节决策

| 决策点 | 推荐 | 备选 |
| --- | --- | --- |
| 启动时行为 | 自动静默下载新记录（符合"启动拉取"设想），出错不打扰 | 只提示数量，点击才下 |
| 云端删除是否回传本地 | **不回传**（管理员删云端，队员本地保留，防误伤） | 跟随删除（不推荐） |
| 日期备注合并 | 云端优先：同日期云端有备注则覆盖本地；云端没有的日期保留本地 | 本地优先 |
| 下载并发 | 顺序逐个（进度清晰、实现简单） | 并发 2-3 个 |
| 下载进度粒度 | 按文件粒度（"第 n/N 个"） | 字节级进度（reqwest 流式，v2） |
| 中转文件去向 | 导入成功后删除（管线已把源文件归档进数据目录，双份没必要） | 保留 |
| 密钥存储 | localStorage 明文（分发令牌可吊销、低敏感，与现有地址存储一致） | —

## 六、错误处理

- 401 密钥错误：设置页红字提示「密钥无效或已吊销」，同步停止
- 网络/超时：单文件失败不阻塞后续，结束时汇总「成功 N · 失败 M」+ 失败原因列表，下次同步自动补
- 同步过程中可取消（复用 cancel_import + 停止后续下载）
- 服务器不可达：启动静默失败，不打扰
