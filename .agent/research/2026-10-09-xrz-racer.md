# 上传 XRZ 文件能否读取内部车手信息

研究日期：2026-10-09。范围：官方资料核对与四份实际云端文件的只读验证；未修改产品代码、上游采集程序或部署。实测结果由主 agent 完成并提供。

## 结论

补充核对本地导入历史后，已找到实际差异：同一组记录的本地 XRK 文件在 XRZ 解压内容后额外追加了车手 RCR 帧和空备注 NTE 帧；现有 XRZ 没有这些追加帧。四组逐字节对比均成立。不能将本地成功导入 XRK 的结果等同于上传的 XRZ 内部也保存了车手。

AiM 官方 DLL 支持读取 XRZ/XRK，官方说明存在 Racer 和 Vehicle 元数据。能否从某份上传 XRZ 的内部取得车手名，取决于该文件实际保存的值。

此次四份实际云端 XRZ 的官方 DLL `get_racer_name` 结果均为空，`get_vehicle_name` 均为 `A04_AF26`。文件名包含车手姓名，但本次没有从这些文件内部取得相应车手值。这个结论只适用于四份已验证样本，不能推广为 XRZ 格式不支持车手。

## 官方资料

AiM 的 [Access AiM Data Files with a DLL](https://aim-sportline.com/docs/racestudio3/html/xrk-dll.html) 明确说明，其 32 位和 64 位 DLL 用于通过外部软件访问 XRZ/XRK 记录数据；DRK 支持标注为 beta。页面的 MATLAB 示例同样明确让用户选择 XRK/XRZ 文件。因此，官方支持范围包含 XRZ，并非只支持未压缩 XRK。

同页说明，Vehicle、Racer、Championship 和 Venue Type 来自用户在赛道会话开始前设置进 AiM 记录仪的数据。Track 则由记录仪从事先通过 RaceStudio 3 下发的赛道中自动识别；Date & Time 是记录仪管理的采集开始时间。这表明 Racer 是会话记录的元数据，官方资料没有说明 DLL 会从上传文件名解析车手名。

该页将完整 DLL 函数说明指向官方示例包内的 `MatLabXRK.h`，并提供 [Visual Studio 示例包](https://www.aim-sportline.com/aim-software-betas/DLL/TestMatLabXRK.zip) 与 [MATLAB 示例包](https://www.aim-sportline.com/aim-software-betas/DLL/TestMatLabXRK_m.zip)。网页正文没有列出 `get_racer_name` 的完整签名或空值语义；本研究中的函数调用结果来自主 agent 使用本地官方 Windows MatLabXRK DLL 的实测。浏览工具不能直接读取 ZIP 内容，不将网页未展示的 API 细节冒充已核对内容。

官方提供的 [PDF 说明](https://www.aim-sportline.com/aim-software-betas/DLL/HowtoAccessXRKFilesDatawithoutAiMSoftware.pdf) 第 1 页同样说明 XRZ/XRK 支持，第 2 页说明 Vehicle/Racer 等字段的设置来源，第 3 页说明示例选择 XRK/XRZ 文件，与网页一致。

## 边界与后续判断

- 官方支持读取 XRZ，且 Racer 是记录仪设置产生的元数据。不能把当前空值归因为 XRZ 格式天然没有车手字段。
- 四份样本的官方读取结果和当前识别的 RCR 帧一致为空；目前没有从这些文件内部找到可读取的车手值。
- 本次结果不证明任意 XRZ 都没有车手，也不证明不存在任何隐藏字段。结论限于官方接口与已检查的样本结构。
- 文件名中的姓名是独立信息来源。若服务器依赖文件名补充车手，应明确它来自文件名，而不是声称从文件内部解析得到。
- 若目标是使未来上传文件能够通过官方 API 返回车手，应在生成/导出时把完整 XRK（含追加 RCR）压缩成 XRZ，或直接在 XRZ 解压内容里写入 RCR 后重新压缩；临时副本已验证官方 DLL 可读，正式上传链路和上游改动另行处理。
