# 工作区目录说明与清理边界

更新：2026-10-17，依据工作区当前状态（版本 1.3.0）。维护文档集中 .agent，旧文档归档到 .agent/archive/2026-10-09；原文有 SHA-256 清单。本轮只更新文档，不删除编译缓存、运行资源或用户数据。

## 目录用途

| 目录 | 管理方式 |
| --- | --- |
| src / src-tauri / crates / config | 产品源码、配置和构建入口，保留 |
| server | 独立服务器与管理员 UI，不随桌面安装器部署 |
| tests | 固定夹具和验证工具，保留 |
| .agent | 当前维护说明、历史归档与旧路径跳转 |
| resources | ffmpeg.exe / ffprobe.exe，打包时映射到安装目录 resources/；.gitignore 忽略，需自备 |
| Data | 开发样本和打包图标，保留被引用资源 |
| TestMatLabXRK | 5 个 AiM DLL，全部被当前打包引用 |
| design-demos | 历史 UI 基准，可归档，不是正式前端入口 |
| output / Logo.jpg | 设计原稿、候选和报告，选定最终版本后整理 |
| node_modules / .pnpm-store | 可重建的 JS 依赖和下载缓存 |
| target | 编译文件、运行工具、安装包和真实数据混合，按子目录清理 |
| .secrets | 本地签名凭据、服务器环境配置和历史备份，Git 忽略，保留并安全备份 |
| .keys | 旧签名位置；新脚本已改为 .secrets/signing，核对迁移后再清理旧副本 |
| .git | 版本历史，保留 |

根 manifest、锁文件、pnpm-workspace.yaml、index.html 与 build.ps1（签名打包）都是有效入口；技能目录 .agents 与文档目录 .agent 区分。

## 工作区与正式安装的差异

核对依据：tauri.conf.json、main.rs、overlay_export.rs、build.ps1。仓库内不含生成的 installer.nsi。

| 内容 | 工作区 | 当前安装器 / 判断 |
| --- | --- | --- |
| 前端和 Rust 后端 | 源码及 target/frontend | 编入 EXE，用户不需要源码或 Node 后端 |
| AiM DLL | TestMatLabXRK、release 根与 aim 副本 | NSIS 释放到安装目录 aim/ |
| FFmpeg / ffprobe | resources/（Git 忽略），release 根另有同名文件 | 1.3.0 起已映射为 resources/，安装后可独立导出；不再属于缺口 |
| aimwifi.exe / aimwifi.pdb | release 根残留 | 无 aim-wifi 成员，代码与安装器无引用，属于清理候选 |
| options-converter.txt | release 根残留 | 无当前代码显式引用，可能为供应商工具生成，属于候选 |
| release 根 5 个 AiM DLL | 与 aim 同名 | 非 NSIS 来源，统一布局并核对加载后可去冗余 |
| data/telemetry.db / datasets | release/data 有实际记录 | 程序按实际 EXE 目录创建；不打包开发机用户数据 |
| PDB / rlib / deps / build | 编译中间文件和调试信息 | 不属于用户运行资源，可重建 |

运行资源布局：安装态 `resource_dir()` 下为 `aim/` 和 `resources/`；便携拷贝时也接受 EXE 同目录 `aim/`、`../resources/aim`。FFmpeg 查找链见 [当前架构](当前架构.md#ffmpeg-资源与查找)，挪动文件前要同步确认这条链，不要只改一处。

## 清理候选与保留范围

2026-10-08 文件大小汇总，硬链接可能重复计数，不保证实际释放量：

- debug 编译产物约 3.9 GiB；deps 内还发现 user/profiles/units.xml，清缓存前保留这类供应商配置。
- release/deps 与 release/build 合计约 2.3 GiB；保留程序、运行工具、data、用户配置和最新安装器。
- 1.3.0 之前的 5 套 NSIS 包及签名已移到 `target/release/bundle/nsis/archive/`，约 54 MiB，可另行存档。
- .agent/evidence 约 26 MiB，历史证据当前保留，可单独归档。
- output 约 16 MiB，属于设计文件，不是都能再生成的缓存。
- JS 依赖和 Python __pycache__ 可重建，可能需要联网恢复；`resources/` 里的 FFmpeg 需重新下载。

target/release/data 中有数据库、导入原文件、raw 和偏好，不能整删 target 或直接 cargo clean。递归清理前核实绝对路径、停止相关进程、明确保留数据。

Data、前端、Overlay、server、design-demos、tests 有重复 Logo/字体/图标，但 import、include_bytes 与 Docker 各自有资源引用。未引用副本可以进一步归一，不能仅凭哈希相同删除。
