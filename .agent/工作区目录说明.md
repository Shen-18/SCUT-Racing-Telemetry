# 工作区文件地图与存放规则

更新：2026-09-11。项目根：`D:/Desktop/SCUTRacingTelemetry`。
本文是新增、移动、清理文件前必须阅读的目录规范。用户说的“agent 文件夹”统一指现有 **`.agent/`**；不再创建平行的 `agent/`、`docs/` 文档目录。

## 进度文档

[工作进度](工作进度.md) 存放当前状态、每次工作日志及待办；由主 agent 按施工手册维护。原始日志与报告仍存放在 evidence 下，不复制到进度文件。

## 一、固定规则
1. 人工维护的项目文档全部放 `.agent/`；配置放 `config/`，代码放对应源码目录，测试和验收脚本放 `tests/`。
2. 根目录仅保留构建/工具发现入口，不按 `.json`、`.toml` 扩展名随意搬动。移动入口会改变 workspace 和命令的工作根。
3. 构建产物集中 `target/`；前端产物为 `target/frontend/`，不再生成根 `dist/`。删除产物前停止构建进程，核实绝对路径。
4. 文档中的相对路径除 Markdown 链接外均相对项目根。历史日志保留原样，不为迁移而修改运行证据。
5. `.agents/`（技能）与 `.agent/`（项目文档）不同；工具管理目录不可当杂物随意删。
6. 新类别先扩充本表，再创建目录。不得把报告、一次性测试脚本和配置散放根目录。

## 二、根目录各文件夹
| 目录 | 内容与作用 | 清理原则 |
|---|---|---|
| `.agent/` | 唯一项目文档中心：施工/蓝图/调用手册、目录规范、ADR、接口说明、验收证据 | 不删除；旧证据可分类归档 |
| `.agents/` | 当前项目安装的 agent skills，含工具要求的 SKILL.md | 工具管理，不手工搬动 |
| `.agy-staff/` | agy 自动生成的任务状态、会话和原始 review 日志 | 活动任务时禁止移动；需留存的报告复制到 .agent/evidence |
| `.workbuddy/` | 既有 WorkBuddy 工具记忆/状态 | 不作为新项目文档位置；暂保留避免破坏工具 |
| `.git/` | Git 历史、索引与分支 | 绝不能当缓存删除 |
| `config/` | 可迁移配置；不是文档中心 | 受版本控制 |
| `crates/` | 7 个 Rust 业务模块 | 源代码，不清理 |
| `src-tauri/` | Tauri 桌面薄壳、构建入口、权限与资源配置 | 源代码，不清理 |
| `src/` | React/TypeScript 前端源码 | 源代码，不清理 |
| `tests/` | 测试夹具、golden 套件、验证脚本及其自测 | 保留原始夹具 |
| `Data/` | 既有 CSV/XRK 样本和图片；AGX、Du、test 等验证输入 | 只读；不得当缓存删除 |
| `TestMatLabXRK/` | AiM/Matlab XRK 供应商参考工程、DLL、样本 | 只读参考；暂保留原路径 |
| `target/` | Rust 生成的编译中间文件、程序和前端打包输出 | 可重建；当前未清空 Rust 编译缓存 |
| `node_modules/` | pnpm 安装的 JS 依赖及命令入口 | 可重新安装，但删除后需 pnpm install |
| `.pnpm-store/` | pnpm 下载/内容寻址缓存，位置由 pnpm-workspace.yaml 指定 | 非源码；不为减少目录数移动现有链接 |

## 三、根目录散列文件为何保留
| 文件 | 用途 | 是否可直接删除/收进 config |
|---|---|---|
| `Cargo.toml` | Rust workspace 清单，列出 crate 和统一依赖版本 | 否；整个 Rust 工程的根入口 |
| `Cargo.lock` | Rust 实际解析版本锁定，便于复现构建 | 不应删；不是临时日志 |
| `package.json` | Node 项目信息、依赖和 dev/build/test/check 命令 | 否；pnpm 在根目录读取它 |
| `pnpm-lock.yaml` | JS 实际依赖版本及完整性锁定 | 不应删；与 package.json 配套 |
| `pnpm-workspace.yaml` | pnpm workspace、esbuild 脚本许可、store 路径配置 | 保持在 workspace 根 |
| `skills-lock.json` | 已安装技能来源/锁定记录 | 工具入口，保留原位置 |
| `index.html` | Vite 页面入口，加载 src/main.tsx | 保留项目根，避免引入额外 Vite root 重映射 |
| `.gitignore` | 防止依赖、缓存和产物提交 Git | 根规则文件，不移动 |

JSON/TOML/YAML 是配置格式，不等于杂物。这些少量根入口是有意保留的；不保留第二份副本。

## 四、内部分类与关键文件
- `.agent/README.md`：文档导航；本文件：目录规范。
- `.agent/Workbuddy_...Construction_Manual.markdown`：施工顺序；`Gemini_...Blueprint.md`：产品蓝图；`agy-staff-调用手册.md`：review 调用方式。
- `.agent/adr/0001~0007`：总架构、IPC、SoA、pyramid、测试、保留备份、便携分发的决策理由。
- `.agent/contracts/`：依赖/接口/目录规则的文字说明。
- `.agent/evidence/step1/`：历史命令日志、状态、review 报告；`reorganization/` 保存本次整理的验证输出。log 和 metadata.json 也是证据，不是运行配置。
- `config/contracts/dependencies.json`：依赖白名单机器源；文字说明在 `.agent/contracts/dependencies.md`。
- `config/frontend/vite.config.ts`：前端服务/打包配置，输出到 `target/frontend`。
- `config/frontend/tsconfig.json`：TypeScript 类型检查规则。
- `config/frontend/eslint.config.js`：JS/TS lint 规则。
- `config/frontend/tailwind.config.js`：Tailwind 扫描范围与令牌映射。
- `tests/tooling/check.ps1`：六道验收总入口（也可根目录执行 pnpm check）。
- `tests/tooling/env.ps1`：仅为当前进程设置 Rust/MSVC 开发环境。
- `tests/tooling/verify-dependencies.ps1`、`verify_dependencies.py`：依赖约束校验入口及实现。
- `tests/tooling/tests/test_dependencies.py`：约束检查器的负例自测，使用临时副本。
- `tests/fixtures/`：固定输入；`tests/golden/`：来源完整性登记；`tests/golden-tests/`：Cargo golden 验证包。
- `crates/telemetry-core`：纯模型/算法；`cache-core`：缓存协议；`aim-ffi`：DLL 边界；`csv-parser`：CSV 解析；`telemetry-store`：持久化；`telemetry-ipc`：IPC；`migrate-v1`：迁移工具。
- 各 crate 的 `Cargo.toml` 是该包自己的清单，`src/lib.rs`/`src/main.rs` 是编译入口，不能集中搬走。
- `src-tauri/Cargo.toml`、`build.rs`、`tauri.conf.json`、`src/main.rs`：桌面包清单、构建脚本、窗口资源配置和程序入口。`capabilities/`、`icons/` 为权限/图标预留位置。
- `src/main.tsx`：挂载 React；`App.tsx`：空白壳；`App.test.tsx`：贴近组件的单元测试；`index.css`、`theme/`：样式；`api/client.ts`：唯一 IPC 边界；其他规划目录按施工步骤填充，不用假实现填满。
- `target/frontend/index.html`、`assets/`：压缩后的页面和 JS/CSS，**不是源码**。可以删除后执行 pnpm build 重建。
